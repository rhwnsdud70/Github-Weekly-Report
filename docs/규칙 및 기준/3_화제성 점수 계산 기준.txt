GitHub 주간 AI·개발 이슈 화제성 점수 계산 규칙 - 최종본

목적
매주 수집된 GitHub AI 및 소프트웨어 개발 관련 후보들 중,
어떤 프로젝트나 사건이 실제로 더 화제가 되었고 개발자가 알아둘 가치가 높은지
일관된 기준으로 평가하기 위한 화제성 점수 규칙을 정의한다.

총점은 100점 만점이며,
구간 점수표 방식으로 평가한다.

==================================================
1. 총점 구조
==================================================

- 최근 7일 Star 증가량: 최대 25점
- 최근 7일 Star 증가율: 최대 20점
- GitHub Trending: 최대 15점
- Issue / PR 활동: 최대 15점
- Fork / Discussions 활동: 최대 5점
- 주요 Release: 최대 10점
- 특별 이벤트: 최대 10점

총점: 100점

==================================================
2. 최근 7일 Star 증가량 - 최대 25점
==================================================

저장소 규모별로 미리 정한 Star 증가 기준값을 T라고 한다.

저장소 규모별 기준값:

현재 Star 100~499
- 기준 T = +50

현재 Star 500~1,999
- 기준 T = +100

현재 Star 2,000~9,999
- 기준 T = +300

현재 Star 10,000~49,999
- 기준 T = +700

현재 Star 50,000 이상
- 기준 T = +1,500

점수표:

- 기준 미만: 0점
- 기준 충족: 10점
- 기준의 1.5배 이상: 15점
- 기준의 2배 이상: 20점
- 기준의 3배 이상: 25점

예시:

현재 Star 1,000인 저장소의 기준 T = +100

- 이번 주 +80 → 0점
- 이번 주 +100 → 10점
- 이번 주 +150 → 15점
- 이번 주 +200 → 20점
- 이번 주 +300 이상 → 25점

원칙:
- 총 Star 수가 아니라 최근 7일 동안의 실제 증가량을 평가한다.
- 대형 저장소와 소형 저장소에 동일한 절대 기준을 적용하지 않는다.

==================================================
3. 최근 7일 Star 증가율 - 최대 20점
==================================================

점수표:

- 5% 미만: 0점
- 5% 이상 ~ 10% 미만: 4점
- 10% 이상 ~ 20% 미만: 8점
- 20% 이상 ~ 50% 미만: 12점
- 50% 이상 ~ 100% 미만: 16점
- 100% 이상: 20점

신규 저장소 보정:
- 생성 30일 이내 신규 저장소는 이 항목 최대 16점으로 제한한다.

이유:
- 신규 저장소는 초기 Star가 작아 증가율이 과도하게 높게 계산될 수 있기 때문이다.

==================================================
4. GitHub Trending - 최대 15점
==================================================

점수표:

- Trending 미진입: 0점
- 30위 이하 또는 낮은 노출: 4점
- Top 16~30: 8점
- Top 6~15: 12점
- Top 1~5: 15점

정확한 순위를 확인하기 어려운 경우 대체 기준:

- 미진입: 0점
- Trending 진입 확인: 10점
- 명확한 상위권: 15점

원칙:
- Trending은 강한 화제성 신호로 사용하지만,
  Trending 여부만으로 최종 선정을 결정하지 않는다.

==================================================
5. Issue / PR 활동 - 최대 15점
==================================================

이 항목은 두 부분으로 나누어 계산한다.

--------------------------------------------------
5-1. 최근 7일 절대 활동량 - 최대 7점
--------------------------------------------------

최근 7일 동안의 신규 Issue 수 + Pull Request 수 합계:

- 0~4건: 0점
- 5~9건: 2점
- 10~29건: 4점
- 30~99건: 6점
- 100건 이상: 7점

--------------------------------------------------
5-2. 이전 7일 대비 활동 증가율 - 최대 8점
--------------------------------------------------

Issue + PR 활동량의 이전 7일 대비 증가율:

- 25% 미만: 0점
- 25% 이상 ~ 50% 미만: 2점
- 50% 이상 ~ 100% 미만: 4점
- 100% 이상 ~ 200% 미만: 6점
- 200% 이상: 8점

최종 Issue / PR 점수:
- 절대 활동량 점수 + 활동 증가율 점수
- 최대 15점

원칙:
- 대형 프로젝트는 평소에도 PR과 Issue가 많을 수 있으므로,
  절대량과 증가율을 함께 평가한다.

==================================================
6. Fork / Discussions 활동 - 최대 5점
==================================================

점수표:

- 변화 거의 없음: 0점
- 소폭 증가: 1점
- 관심 증가 확인: 2점
- 뚜렷한 증가: 3점
- 매우 활발: 4점
- 급격한 증가: 5점

원칙:
- Fork는 실제 사용·실험 의향을 보조적으로 보여주는 지표로 본다.
- Discussions는 커뮤니티 토론 활성도를 보조적으로 반영한다.
- 정확한 수치 확보가 어려운 경우 정성적 판단을 허용한다.
- 정성 평가를 사용할 경우 근거를 함께 기록한다.

==================================================
7. 주요 Release - 최대 10점
==================================================

점수표:

- Release 없음 / 단순 Patch: 0점
- 의미 있는 Minor Release: 2점
- 주요 기능 추가: 4점
- 대규모 성능 개선: 5점
- v1.0 정식 출시: 7점
- Major Version Release: 7점
- Breaking Change 포함: 8점
- 생태계 영향이 매우 큰 Release: 10점

원칙:
- 하나의 Release가 여러 조건을 만족해도 점수를 합산하지 않는다.
- 가장 높은 하나의 점수만 적용한다.
- 단순 버그 수정이나 경미한 패치는 기본적으로 0점으로 처리한다.

==================================================
8. 특별 이벤트 - 최대 10점
==================================================

점수표:

- 경미한 정책 / 운영 변화: 2점
- 주요 커뮤니티 논란: 5점
- 라이선스 변경: 6점
- 중요한 API 폐기 / 변경: 6점
- 프로젝트 유지보수 중단: 7점
- High 보안 취약점: 7점
- 프로젝트 종료: 8점
- Critical 보안 취약점: 10점
- Remote Code Execution: 10점
- Supply-chain 공격: 10점

원칙:
- 특별 이벤트가 여러 개 발생해도 기본 점수는 가장 높은 사건 하나를 적용한다.
- 여러 사건이 동시에 발생한 경우 최종 설명에서 복합 영향도를 별도로 서술한다.

==================================================
9. 강제 검토 예외 규칙
==================================================

다음 사건은 총점이 낮더라도 최종 보고서 후보에서 자동 탈락시키지 않는다.

강제 검토 대상:

- Critical Security Vulnerability
- Remote Code Execution
- Supply-chain Attack
- 대규모 Credential Exposure
- 광범위한 Authentication Bypass
- 주요 라이선스 변경
- 프로젝트 종료
- 프로젝트 유지보수 중단
- 널리 사용되는 API의 중요한 폐기
- 개발 생태계에 큰 영향을 주는 Breaking Change

이 경우:
- 화제성 점수와 별도로 "강제 검토 후보" 표시를 추가한다.
- 최종 뉴스 가치 평가에서 반드시 검토한다.

==================================================
10. 최종 등급 기준
==================================================

총점 85~100:
- 등급: 핵심 이슈
- 처리: 최우선 선정 후보

총점 70~84:
- 등급: 매우 화제
- 처리: 우선 선정 후보

총점 55~69:
- 등급: 주목할 만함
- 처리: 일반 최종 후보

총점 40~54:
- 등급: 관찰 대상
- 처리: 중요도와 뉴스 가치에 따라 선택적 포함

총점 0~39:
- 등급: 낮은 우선순위
- 처리: 기본적으로 제외

==================================================
11. 최종 선정 원칙
==================================================

화제성 점수만으로 최종 보고서를 결정하지 않는다.

최종 선정 시 다음 요소를 함께 본다.

1. 화제성 점수
2. AI / 개발 관련성
3. 뉴스 가치
4. 실제 개발자에게 미칠 영향
5. 이전 주 보고서와의 중복 여부
6. 정보의 신뢰성
7. 강제 검토 예외 여부

예시:

사례 A
- 화제성 점수 88점
- 하지만 단순 밈성 프로젝트
→ 최종 제외 가능

사례 B
- 화제성 점수 48점
- 널리 사용되는 라이브러리의 Critical 취약점
→ 강제 검토 후 최종 포함 가능

13. 핵심 원칙
==================================================

- 총 Star 수보다 최근 7일 변화량을 더 중요하게 본다.
- 절대 증가량과 증가율을 함께 본다.
- 대형 저장소와 소형 저장소를 같은 기준으로 평가하지 않는다.
- Trending은 중요한 신호지만 유일한 기준으로 사용하지 않는다.
- Issue / PR은 절대 활동량과 증가율을 같이 평가한다.
- Release는 버전 번호보다 실제 영향도를 중요하게 본다.
- 보안, 라이선스, 프로젝트 종료 등은 인기와 별도로 중요하게 다룬다.
- 확인할 수 없는 수치를 임의로 생성하지 않는다.
- 화제성 점수는 최종 판단을 돕는 도구이며,
  최종 목적은 "이번 주 개발자가 실제로 알아둘 가치가 있는 GitHub 이슈"를 고르는 것이다.
