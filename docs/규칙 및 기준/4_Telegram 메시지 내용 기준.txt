# Telegram 주간 GitHub AI·개발 이슈 메시지 골격

## 1. 보고서 제목

메시지 가장 위에 해당 주간 보고서의 성격이 바로 드러나도록 작성한다.

포함 내용:
- "GitHub 주간 AI·개발 이슈"라는 제목
- 조사 기간
- 필요하면 해당 주차 표시

작성 방식:
- 짧고 명확하게 작성
- 이모지를 사용해 시각적으로 구분
- 날짜는 시작일과 종료일을 모두 표시

예시 형태:
🔥 GitHub 주간 AI·개발 이슈  
기간: YYYY.MM.DD ~ YYYY.MM.DD

---

## 2. 이번 주 핵심 요약

TOP 5 내용을 읽기 전에 이번 주 전체 흐름을 빠르게 파악할 수 있도록 작성한다.

포함 내용:
- 이번 주 공통적으로 나타난 주요 기술 흐름 3개 내외
- 가장 눈에 띄는 변화
- 필요하면 가장 중요한 분야를 한 줄로 강조

작성 방식:
- 각 항목은 한두 문장 이내
- 세부 설명보다 전체 흐름 위주
- TOP 5에 등장하는 내용을 단순 반복하지 말고 공통 패턴을 정리

---

# TOP 5 이슈

TOP 5는 모두 동일한 구조로 작성한다.

각 항목은 단순 요약이 아니라 하나의 작은 주간 리포트처럼 작성한다.

---

## 3. 순위 + 프로젝트 또는 이슈 이름

포함 내용:
- 순위
- 프로젝트명 또는 주요 Issue명
- 분야
- 화제성 점수
- 화제성 등급

작성 방식:
- 한눈에 구분되도록 작성
- 분야는 AI Agent, LLM, Framework, Security 등의 짧은 태그 형태
- 점수와 중요도를 함께 보여준다.

---

## 4. 주요 지표

해당 프로젝트가 이번 주 실제로 얼마나 관심을 받았는지 보여주는 정량 정보 영역이다.

가능하면 포함:
- 현재 총 Star 수
- 최근 7일 Star 증가량
- 최근 7일 Star 증가율
- GitHub Trending 여부 및 순위
- 최근 Issue / PR 활동량
- Fork 또는 Discussion 증가 여부
- 주요 Release 존재 여부

작성 방식:
- 짧은 bullet 형식
- 수치 중심
- 확인할 수 없는 수치는 임의로 작성하지 않는다.
- 정확한 수치를 알 수 없으면 "정확한 수치 확인 어려움"이라고 명시한다.

---

## 5. 왜 화제인가

각 TOP 5 항목에서 가장 중요한 설명 영역이다.

포함 내용:
- 이번 주 관심이 증가한 직접적인 계기
- 어떤 기능, 발표, Release, Issue 또는 사건이 있었는지
- 기존 프로젝트나 기술과 무엇이 달랐는지
- 왜 개발자들이 해당 프로젝트를 공유하고 테스트하기 시작했는지
- 관심 증가가 단순한 일시적 유행인지, 기술적인 이유가 있는지

작성 방식:
- 단순히 "Star가 증가해서 화제"라고 작성하지 않는다.
- 사건의 배경 → 직접적인 계기 → 관심이 커진 이유 순으로 설명한다.
- 필요하면 여러 문단으로 작성한다.
- TOP 5 중 가장 충분한 설명이 필요한 파트이므로 길이를 억지로 줄이지 않는다.

---

## 6. 핵심 내용

프로젝트나 사건 자체를 이해할 수 있도록 설명한다.

포함 내용:
- 프로젝트가 무엇을 하는지
- 주요 기능
- 기술 구조 또는 특징
- 기존 유사 프로젝트와의 차이
- 이번 업데이트에서 달라진 부분

작성 방식:
- 지나치게 홍보성 표현을 사용하지 않는다.
- 기술을 처음 접한 개발자도 이해할 수 있도록 설명한다.
- 필요하다면 기존 기술과 비교한다.

---

## 7. 개발자에게 중요한 이유

해당 이슈가 실제 개발자에게 어떤 의미가 있는지를 설명한다.

포함 가능한 내용:
- 개발 생산성 변화
- 기존 기술 또는 프레임워크를 대체할 가능성
- 새로운 개발 패턴 등장
- API 변화
- 인프라 변화
- 비용 변화
- 성능 변화
- 보안 영향
- 유지보수 영향
- 향후 생태계에 미칠 영향

작성 방식:
- 프로젝트 소개를 반복하지 않는다.
- "그래서 개발자 입장에서 무엇이 달라지는가?"에 답한다.

---

## 8. 개발자들은 무엇을 이야기하고 있나

GitHub 커뮤니티의 실제 반응을 요약한다.

주요 출처:
- GitHub Issues
- GitHub Discussions
- Pull Request 댓글
- Repository 내부 기술 토론

내용을 가능하면 다음 세 부분으로 나눈다.

### 긍정적인 의견
포함 내용:
- 개발자들이 높게 평가하는 기능
- 기존 도구보다 나아졌다고 보는 점
- 실제 사용 경험에서 긍정적으로 평가되는 부분

### 우려하거나 비판하는 의견
포함 내용:
- 버그
- 안정성
- 성능
- API 설계
- 유지보수
- 보안
- 라이선스
- 과도한 기대 등에 대한 우려

### 논쟁 중인 부분
포함 내용:
- 커뮤니티 의견이 갈리는 부분
- 기술 방향성에 대한 논쟁
- 기존 프로젝트를 대체할 수 있는지에 대한 의견 차이
- 설계 방식이나 정책을 둘러싼 논쟁

작성 방식:
- 개별 댓글을 단순 나열하지 않는다.
- 여러 의견에서 나타나는 공통적인 패턴을 정리한다.
- 각 의견이 왜 나오는지도 함께 설명한다.
- 실제 근거가 충분하지 않으면 커뮤니티 전체 의견인 것처럼 일반화하지 않는다.

---

## 9. 주의할 점

프로젝트 또는 사건을 과도하게 긍정적으로 바라보지 않도록 위험 요소를 정리한다.

가능한 내용:
- 아직 초기 단계인지
- Production 사용이 가능한 수준인지
- 안정성 검증 여부
- 알려진 버그
- 플랫폼 호환성
- 성능 검증 부족
- 보안 문제
- 라이선스 문제
- API 변경 가능성
- 과도한 홍보 또는 일시적 유행 가능성

작성 방식:
- 실제 확인되는 문제를 중심으로 작성한다.
- 특별한 주의점이 없으면 억지로 작성하지 않는다.

---

## 10. 관련 링크

각 TOP 5 항목 마지막에 원문을 직접 확인할 수 있는 링크를 제공한다.

우선순위:
1. Repository
2. 주요 Issue
3. 주요 Discussion
4. 중요한 Pull Request
5. Release 페이지

작성 방식:
- Repository 링크는 반드시 포함
- Issue / Discussion은 해당 이슈를 이해하는 데 중요한 것만 1~3개 정도 선택
- 불필요하게 많은 링크를 나열하지 않는다.

---

# TOP 5 이후

## 11. 이번 주 GitHub 전체 트렌드

TOP 5를 모두 분석한 뒤 공통적으로 보이는 개발 생태계 흐름을 정리한다.

포함 내용:
- 공통 기술 키워드
- 반복해서 나타난 개발 패턴
- 특정 분야의 성장
- 새로운 오픈소스 방향성
- 개발자들의 관심 이동

작성 방식:
- 3~5개 정도
- 단순히 TOP 5 이름을 다시 나열하지 않는다.
- "이번 주 전체를 보면 어떤 방향으로 움직이고 있는가?"를 설명한다.

---

## 12. 다음 주 관찰 프로젝트

이번 주 TOP 5에는 포함되지 않았지만 다음 주에 화제가 될 가능성이 있는 프로젝트를 소개한다.

개수:
- 최대 3개

포함 내용:
- 프로젝트명
- 현재 성장 신호
- 왜 다음 주에 관찰할 가치가 있는지

작성 방식:
- 긴 설명은 필요하지 않음
- 아직 확정적인 화제라고 표현하지 않는다.
- "관찰 후보"라는 성격을 명확히 한다.

---

## 13. 데이터 및 신뢰성 안내

보고서 마지막에 데이터 관련 주의사항을 간단히 표시한다.

포함 내용:
- 정확한 증가량을 확인하지 못한 항목의 처리 방식
- 추정치 사용 여부
- 커뮤니티 의견의 출처
- 특정 수치의 제한사항

작성 원칙:
- 확인되지 않은 수치를 사실처럼 작성하지 않는다.
- 추정값은 반드시 추정임을 표시한다.
- 커뮤니티 의견은 실제 GitHub 토론을 기반으로 작성한다.
- 소수 의견을 전체 개발자 의견처럼 표현하지 않는다.

---

# 전체 메시지 흐름

1. 제목 및 조사 기간
2. 이번 주 핵심 요약
3. TOP 1
4. TOP 2
5. TOP 3
6. TOP 4
7. TOP 5
8. 이번 주 GitHub 전체 트렌드
9. 다음 주 관찰 프로젝트
10. 데이터 및 신뢰성 안내

TOP 1~5는 모두 동일한 상세 구조를 사용한다.

각 TOP 항목 내부 순서:

순위 / 프로젝트명  
→ 분야 / 화제성 점수  
→ 주요 지표  
→ 왜 화제인가  
→ 핵심 내용  
→ 개발자에게 중요한 이유  
→ 개발자들은 무엇을 이야기하고 있나  
→ 주의할 점  
→ 관련 GitHub 링크
