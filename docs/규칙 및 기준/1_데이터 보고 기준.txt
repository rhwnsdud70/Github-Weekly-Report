매주 최근 7일 동안 GitHub에서 화제가 된 AI 및 소프트웨어 개발 관련 이슈를 조사하고 정리한다.

조사 대상은 단순히 전체 Star 수가 많은 유명 저장소가 아니라, 최근 7일 동안 새롭게 관심이 급증했거나 개발자 커뮤니티에서 활발하게 논의된 저장소, 프로젝트, 릴리스, Issue를 중심으로 한다.

## 1. 조사 대상 범위

다음 분야를 우선적으로 조사한다.

- AI / Machine Learning
- LLM
- AI Agent
- AI Coding Agent
- 개발자 도구
- IDE / 코드 에디터
- 프로그래밍 언어
- 웹 / 앱 프레임워크
- 데이터베이스
- DevOps
- Cloud
- 오픈소스 개발 도구
- 보안
- 개발 생산성 도구
- 새로운 라이브러리 및 SDK
- 주요 개발 플랫폼 및 인프라 기술

단순 개인 프로젝트, 밈성 프로젝트, 개발과 직접적인 관련성이 낮은 저장소는 중요도가 매우 높은 경우가 아니라면 제외한다.

## 2. 화제성 판단 기준

각 후보 프로젝트 또는 이슈에 대해 다음 요소를 종합적으로 평가한다.

### 최근 7일 Star 증가량
최근 7일 동안 Star가 얼마나 증가했는지를 가장 중요한 지표 중 하나로 사용한다.

기존 전체 Star 수보다는 최근 증가량을 우선한다.

### Star 증가율
기존 규모에 비해 최근 관심이 얼마나 빠르게 증가했는지를 평가한다.

예를 들어 기존 Star가 적은 프로젝트가 짧은 기간에 크게 성장했다면 높은 평가를 부여한다.

### GitHub Trending 여부
최근 7일 동안 GitHub Trending에 등장했거나 상위권에 위치한 프로젝트는 높은 화제성을 가진 것으로 평가한다.

### Issue 활동
최근 새롭게 생성된 Issue 수, Issue 댓글 수, 활발한 기술 논의 여부를 확인한다.

특정 Issue 하나가 프로젝트 전체보다 더 큰 관심을 받은 경우 해당 Issue 자체를 주요 이슈 후보로 포함할 수 있다.

### Pull Request 활동
최근 PR 생성 및 Merge 활동이 크게 증가했거나 주요 기능 개발이 활발하게 진행되고 있는지 확인한다.

### Fork 증가
최근 Fork가 급격히 증가했는지 확인하여 실제 개발자들이 해당 프로젝트를 사용하거나 수정하려는 움직임이 있는지 평가한다.

### Discussions 활동
GitHub Discussions에서 질문, 기술 토론, 프로젝트 방향성 등에 대한 활발한 논의가 발생했는지 평가한다.

### 주요 Release
다음과 같은 중요한 릴리스가 있었는지 확인한다.

- v1.0 또는 정식 버전 출시
- 대규모 업데이트
- 주요 신규 기능
- AI 모델 또는 API 지원 추가
- 성능 대폭 개선
- Breaking Change
- 아키텍처 변경

### 특별 이슈
다음과 같은 사건은 Star 수와 무관하게 높은 중요도를 부여한다.

- 심각한 보안 취약점
- 라이선스 변경
- 프로젝트 종료 또는 유지보수 중단
- API 폐기
- 대규모 장애 또는 버그
- 프로젝트 방향성 변경
- 유명 프로젝트의 정책 변화
- 커뮤니티 논란
- 중요한 기술적 결정

## 3. 화제성 점수

가능한 경우 다음 기준을 참고하여 100점 만점으로 평가한다.

- 최근 7일 Star 증가량: 30점
- Star 증가율: 20점
- GitHub Trending: 15점
- Issue / PR 활동: 15점
- Fork 증가: 5점
- Discussions 활동: 5점
- 주요 Release: 5점
- 특별 이슈: 5점

점수가 정확히 계산되기 어려운 경우에는 수치화 가능한 데이터와 정성적인 판단을 함께 사용한다.

대략 60점 이상의 후보를 우선적으로 주간 주요 이슈에 포함한다.

단, 보안 사고, 프로젝트 종료, 라이선스 변경 등 개발 생태계에 큰 영향을 미치는 사건은 점수와 관계없이 포함할 수 있다.

## 4. 3단계 필터

수집한 후보를 다음 단계로 필터링한다.

### 1단계: 화제성

GitHub에서 실제로 최근 관심이 증가했는가?

Star, Trending, Issue, PR, Fork, Discussion 등의 데이터를 종합한다.

### 2단계: 개발 관련성

AI 또는 소프트웨어 개발 생태계와 직접적인 관련이 있는가?

개발자에게 실질적인 기술적 의미가 없는 프로젝트는 제외한다.

### 3단계: 뉴스 가치

개발자가 이번 주에 알아둘 가치가 있는 변화인가?

단순 인기 프로젝트보다는 다음 요소를 우선한다.

- 새로운 기술 등장
- 빠르게 성장하는 오픈소스
- 개발 방식 변화
- 주요 프레임워크 업데이트
- AI 개발 생태계 변화
- 보안 문제
- 중요한 오픈소스 정책 변화
- 개발 생산성에 큰 영향을 주는 도구

## 5. 중복 방지

이미 이전 주간 보고서에서 소개한 프로젝트가 다시 등장할 경우 단순히 계속 인기 있다는 이유만으로 반복해서 소개하지 않는다.

다만 다음과 같은 새로운 변화가 발생했다면 다시 소개할 수 있다.

- 새로운 대규모 Release
- Star 또는 사용자가 다시 급증
- 중요한 보안 이슈
- 주요 기능 추가
- 라이선스 또는 정책 변화
- 중요한 논란 발생

이 경우 이전에 소개한 내용과 무엇이 달라졌는지를 명확하게 설명한다.

## 6. 최종 선정 개수

매주 약 5~10개의 주요 이슈를 선정한다.

억지로 개수를 채우지 않는다.

해당 주에 실제로 중요한 이슈가 4개뿐이라면 4개만 소개할 수 있다.

반대로 중요한 이슈가 많은 주에는 최대 10개 정도까지 포함한다.

## 7. 결과 작성 형식

각 이슈는 다음 형식으로 작성한다.

### 순위. 프로젝트 또는 이슈 이름

GitHub 저장소:
링크

분야:
AI Agent / LLM / 개발도구 / 프레임워크 / 보안 등

이번 주 주요 지표:
- 최근 7일 Star 증가량
- 현재 총 Star 수
- Star 증가율
- Trending 여부
- Issue / PR 활동
- 필요한 경우 Fork 또는 Discussion 활동

화제성 점수:
100점 만점 기준

왜 화제가 되었는가:
이번 주 관심이 증가한 직접적인 이유를 2~4문장으로 설명한다.

핵심 내용:
프로젝트, 기술 또는 사건이 무엇인지 비전공자도 이해할 수 있도록 간단히 설명한다.

개발자에게 중요한 이유:
실제 개발자 또는 AI 개발자 입장에서 어떤 영향을 줄 수 있는지 설명한다.

주의할 점:
초기 프로젝트, 과도한 홍보, 안정성 문제, 보안 문제, 라이선스 문제 등이 있다면 함께 설명한다.

## 8. 보고서 마지막 요약

마지막에 반드시 다음 내용을 추가한다.

### 이번 주 GitHub 개발 트렌드

이번 주 전체 이슈에서 공통적으로 나타난 기술적 흐름을 3~5개로 정리한다.

예:

- AI Coding Agent 경쟁 심화
- 로컬 LLM 실행 도구 증가
- MCP 생태계 확대
- Rust 기반 개발 도구 증가
- AI 인프라 최적화 프로젝트 증가

### 이번 주 가장 주목할 이슈

선정된 항목 중 개발 생태계에 가장 영향력이 클 것으로 보이는 이슈 하나를 선택한다.

선정 이유를 3~5문장으로 설명한다.

### 다음 주 관찰할 프로젝트

이번 주 주요 이슈에는 포함되지 않았지만 빠르게 성장하고 있어 다음 주에 주목할 가치가 있는 프로젝트가 있다면 최대 3개까지 소개한다.

## 9. 조사 원칙

가능한 한 최신 GitHub 데이터를 기준으로 판단한다.

단순 홍보 문구보다 실제 Repository, Release, Issue, Pull Request, Discussions 등의 정보를 우선한다.

확인되지 않은 내용을 사실처럼 작성하지 않는다.

정확한 Star 증가량 또는 활동량을 확인할 수 없는 경우 추정값을 사실처럼 제시하지 말고 "정확한 증가량 확인 어려움"이라고 표시한다.

유명 프로젝트라는 이유만으로 포함하지 않는다.

이번 주에 실제로 새로운 변화가 있었는지를 가장 중요하게 평가한다.
