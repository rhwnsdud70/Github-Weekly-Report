# GitHub 주간 AI·개발 이슈 실행 스케줄 규칙

## 1. 실행 주기

- **실행 요일:** 매주 일요일
- **실행 시간:** 오후 7시 (19:00)
- **기준 시간대:** 대한민국 표준시 KST (UTC+9)
- **실행 빈도:** 주 1회

---

## 2. 데이터 조사 기간

매주 리포트는 정확히 이전 실행 시점부터 현재 실행 시점까지의 데이터를 조사한다.

**조사 시작:** 이전 일요일 19:00 KST  
**조사 종료:** 이번 일요일 19:00 KST

즉, 매번 정확히 **7일(168시간)**을 하나의 조사 기간으로 사용한다.

예시:

- 이전 실행: 2026.10.04 19:00 KST
- 현재 실행: 2026.10.11 19:00 KST
- 조사 기간: 2026.10.04 19:00 ~ 2026.10.11 19:00 KST

다음 실행에서는:

- 2026.10.11 19:00 ~ 2026.10.18 19:00 KST

를 조사한다.

이 방식을 사용하여 조사 기간 사이에 누락되는 시간이 발생하지 않도록 한다.

---

## 3. 경계 시각 처리

조사 기간이 서로 겹치거나 동일 데이터가 중복 집계되지 않도록 다음 방식으로 처리한다.

- 시작 시각: **포함**
- 종료 시각: **미포함**

개념적으로 다음 범위를 사용한다.

`이전 일요일 19:00 이상 ~ 이번 일요일 19:00 미만`

예:

`2026.10.04 19:00 <= 이벤트 시각 < 2026.10.11 19:00`

정확히 이번 일요일 19:00에 발생한 데이터는 다음 주 조사 기간에 포함한다.

---

## 4. 주간 데이터 비교 기준

화제성 계산을 위해 필요할 경우 현재 조사 기간과 직전 조사 기간을 비교한다.

현재 기간:
`이번 주 - 7일 ~ 이번 주 실행 시점`

비교 기간:
`이번 주 - 14일 ~ 이번 주 - 7일`

이를 이용해 다음 항목의 전주 대비 변화를 계산한다.

- Star 증가
- Issue 활동
- Pull Request 활동
- Fork 활동
- Discussions 활동

필요한 경우 최근 30일 데이터는 장기 추세 확인을 위한 보조 자료로만 사용한다.

## 5. 자동화 실행 흐름

매주 일요일 19:00 KST에 다음 작업을 순서대로 실행한다.

1. 조사 기간 확정
2. GitHub 데이터 수집
3. 후보 Repository / Issue / Release 수집
4. 중복 제거
5. 화제성 점수 계산
6. TOP 5 선정
7. 서술형 콘텐츠 생성
8. Telegram 메시지 생성
9. Telegram 메시지 발송

---

## 6. Telegram 발송 시점

GitHub 데이터 분석 및 보고서 생성이 완료된 후 같은 실행 작업 안에서 Telegram 발송을 진행한다.

발송 순서는 사전에 정한 Telegram 메시지 규칙을 따른다.

1. 주간 요약
2. TOP 1
3. TOP 2
4. TOP 3
5. TOP 4
6. TOP 5
7. 특별 경고 — 존재할 경우에만
8. 주간 전체 트렌드 및 다음 주 관찰 프로젝트

---

## 7. Telegram 전송 실패 처리

각 메시지 전송이 실패할 경우 재전송을 시도한다.

전송 정책:

- 최초 전송 시도: 1회
- 실패 시 재시도: 최대 2회
- 최대 총 전송 시도: 3회

처리 흐름:

`최초 전송 → 실패 → 1차 재시도 → 실패 → 2차 재시도`

2차 재시도까지 실패하면 해당 메시지는 더 이상 전송하지 않는다.

---

## 8. 최종 전송 실패 처리

최대 2회의 재시도 후에도 전송되지 않은 메시지는 해당 주에 추가로 재전송하지 않는다.

또한:

- 다음 주 리포트에 실패한 메시지를 합쳐 보내지 않는다.
- 동일 메시지를 다음 실행에서 자동 재전송하지 않는다.
- 해당 주 리포트의 분석 결과 자체를 다음 주 TOP 5 선정에 중복 반영하지 않는다.

가능하다면 전송 실패 여부는 내부 실행 기록에 남긴다.

---

## 9. 일부 메시지만 실패한 경우

Telegram 리포트는 여러 개의 메시지로 분리되어 있으므로 일부 메시지만 실패할 수 있다.

예:

- 주간 요약 → 성공
- TOP 1 → 성공
- TOP 2 → 실패
- TOP 3 → 성공

이 경우 TOP 2만 최대 2회 재시도한다.

TOP 2가 최종 실패하더라도 TOP 3 이후 메시지 발송은 계속 진행한다.

즉, **한 메시지의 실패가 전체 주간 리포트 발송을 중단시키지 않도록 한다.**
