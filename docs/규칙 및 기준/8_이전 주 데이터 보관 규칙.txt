# GitHub 주간 AI·개발 이슈 이전 주 데이터 보관 규칙

## 1. 목적

이전 주 데이터를 저장하는 목적은 다음과 같다.

- 최근 7일 Star 증가량을 정확하게 계산
- 이전 주와의 화제성 점수 변화 확인
- 같은 프로젝트가 반복적으로 선정되는 문제 방지
- 이전에 소개한 프로젝트의 재선정 필요성 판단
- 다음 주 관찰 프로젝트의 성장 추적
- 장기간 관심이 이어지는 프로젝트의 흐름 확인

---

## 2. 저장 기준 시점

매주 일요일 19:00 KST의 자동화 실행이 완료된 뒤 해당 주의 데이터를 저장한다.

기준 시각:

- 매주 일요일 19:00 KST
- 해당 시점의 Repository 상태를 주간 Snapshot으로 저장

다음 주 분석에서는 직전 주 Snapshot과 현재 데이터를 비교한다.

---

# 3. 지난주 TOP 5 저장

매주 선정된 TOP 5 프로젝트를 별도로 저장한다.

각 TOP 5 항목에 대해 다음 정보를 기록한다.

- 순위
- Repository 이름
- Repository 고유 식별 정보
- Repository URL
- 분야
- 화제성 점수
- 화제성 등급
- 선정 이유
- 주요 이슈 요약
- 주요 Release
- 주요 Issue
- 주요 Security 이벤트
- 주요 License / API 변화
- 소개 날짜

### 활용 목적

다음 주 같은 프로젝트가 다시 후보가 되었을 때:

- 이전 주에도 등장했는지 확인
- 새로운 변화가 실제로 있었는지 확인
- 단순 반복인지 재선정할 가치가 있는지 판단
- 재선정하는 경우 지난주와 무엇이 달라졌는지 설명

---

# 4. 이전 화제성 점수 저장

각 후보 프로젝트의 직전 화제성 점수를 저장한다.

가능하면 TOP 5뿐 아니라 주요 후보군에도 적용한다.

저장 항목:

- Repository 식별 정보
- 측정 주차
- 화제성 점수
- 화제성 등급

예:

Project A  
지난주 점수: 58  
이번주 점수: 79  
변화: +21

### 활용 목적

- 관심도가 상승하고 있는지 확인
- 화제성이 급격히 증가한 프로젝트 탐지
- 관찰 대상이 실제 주요 이슈로 성장했는지 판단
- 연속 선정 시 재선정 근거로 사용

점수 변화는 보조 신호로 사용하며,
점수가 상승했다는 이유만으로 자동 재선정하지 않는다.

---

# 5. 이전 Star 수 저장

모든 주요 후보 Repository에 대해 매주 기준 시점의 Star 수를 저장한다.

필수 저장 항목:

- Repository 식별 정보
- Repository 이름
- 측정 시각
- 현재 Star 수

예:

Repository: Project A  
측정 시각: 2026.10.11 19:00 KST  
Star: 12,400

다음 주:

측정 시각: 2026.10.18 19:00 KST  
Star: 15,900

최근 7일 Star 증가량:

15,900 - 12,400 = +3,500

### 활용 원칙

가능하면 최근 7일 Star 증가량을 외부 추정값에 의존하지 않고,
직전 주 Snapshot과 현재 Snapshot의 차이로 직접 계산한다.

이 방식으로 계산한 값이 우선 기준이다.

---

# 6. 이전에 소개한 프로젝트 기록

TOP 5 또는 특별 경고 등에서 실제 Telegram 보고서에 등장한 프로젝트는 별도 이력으로 저장한다.

저장 항목:

- Repository 식별 정보
- Repository 이름
- 최초 소개 날짜
- 최근 소개 날짜
- 총 소개 횟수
- 최근 선정 순위
- 최근 화제성 점수
- 최근 선정 이유

예:

Project A

최초 소개: 2026.09.13  
최근 소개: 2026.10.11  
총 소개 횟수: 3  
최근 선정 이유: v2.0 Major Release

### 활용 목적

- 유명 프로젝트가 매주 반복되는 현상 방지
- 이전에 소개한 프로젝트의 재선정 필요성 평가
- 프로젝트의 장기 관심도를 추적

---

# 7. 중복 방지 규칙

이전에 소개한 프로젝트가 다시 후보로 올라온 경우 단순히 점수가 높다는 이유만으로 재선정하지 않는다.

다음과 같은 새로운 변화가 없으면 기본적으로 반복 소개하지 않는다.

- 새로운 Major Release 없음
- 중요한 기능 추가 없음
- 보안 사건 없음
- 라이선스 변경 없음
- API 변화 없음
- Star 재급증 없음
- 중요한 Issue / Discussion 증가 없음
- 프로젝트 방향성 변화 없음

반대로 다음 중 하나 이상이 발생하면 재선정할 수 있다.

- Major Release
- v1.0 또는 정식 출시
- Star의 새로운 급증
- Critical / High Security 사건
- 라이선스 변경
- 중요 API 변경
- 프로젝트 종료 또는 유지보수 중단
- 대규모 Breaking Change
- 새로운 기술적 논쟁
- 개발 생태계에 영향을 줄 중요한 사건

재선정하는 경우 반드시:

"지난번 소개 이후 무엇이 달라졌는가"

를 Telegram 메시지에서 설명한다.

---

# 8. 다음 주 관찰 프로젝트 저장

매주 Telegram 마지막 메시지에서 선정한 최대 3개의 관찰 프로젝트를 별도 저장한다.

저장 항목:

- Repository 식별 정보
- Repository 이름
- URL
- 당시 Star 수
- 당시 화제성 점수
- 선정 당시 성장 신호
- 관찰 대상으로 선정한 이유
- 다음 주 확인할 항목

예:

Project X

당시 Star: 1,300  
화제성 점수: 49

관찰 이유:
최근 7일 Star 증가율 +180%

다음 주 확인:
- 성장세 지속 여부
- Trending 진입 여부
- Release 발생 여부
- Issue / PR 활동 증가 여부

---

# 9. 관찰 프로젝트의 다음 주 처리

다음 주 데이터 수집 시 이전 주 관찰 프로젝트는 우선 확인 대상으로 둔다.

확인 항목:

- Star 증가
- 화제성 점수 변화
- Trending 진입
- Issue / PR 증가
- 주요 Release
- Security 사건
- 커뮤니티 논의 증가

처리:

관심 지속 또는 상승:
→ 일반 후보군 또는 TOP 5 후보로 승격

성장 정체:
→ 관찰 목록에서 제외 가능

새로운 대형 사건 발생:
→ 강제 검토 후보

---

# 10. Repository 식별 기준

Repository 이름만으로 프로젝트를 구분하지 않는다.

가능하면 다음 우선순위를 사용한다.

1. GitHub 고유 Repository ID
2. canonical Repository URL
3. Owner + Repository 이름

이유:

- Repository 이름 변경
- 조직 이전
- Owner 변경
- 동일 이름 Repository 존재

등이 발생해도 동일 프로젝트를 안정적으로 추적하기 위해서다.

---

---

# 12. 다음 주 분석 흐름

이번 주 데이터 수집
→ Repository 식별 정보로 이전 데이터 매칭
→ 직전 Star Snapshot 조회
→ 최근 7일 Star 증가량 계산
→ 이전 화제성 점수 조회
→ 점수 변화 계산
→ 과거 소개 여부 확인
→ 이전 주 Watchlist 여부 확인
→ 신규 변화 여부 확인
→ 중복 방지 규칙 적용
→ 최종 TOP 5 선정

---

# 13. 데이터 보관 기간

가능하면 주간 데이터를 장기 보관한다.

권장:

- 최근 4주: 상세 데이터 유지
- 최근 3개월: 주요 후보 및 점수 기록 유지
- 그 이전: 최소한 소개 이력과 주요 이벤트 기록 유지

이를 통해 단기 상승과 장기 추세를 모두 확인할 수 있다.

---

# 14. 핵심 저장 데이터

최소한 다음 5개 데이터는 반드시 유지한다.

1. 지난주 TOP 5
2. 이전 화제성 점수
3. 이전 Star 수
4. 이전에 소개한 프로젝트
5. 다음 주 관찰 프로젝트

이 5개 데이터를 다음 주 분석의 기준 데이터로 사용한다.

---

# 15. 핵심 원칙

- 주간 Snapshot은 항상 동일한 기준 시각인 일요일 19:00 KST에 저장한다.
- Star 증가량은 가능하면 Snapshot 차이로 직접 계산한다.
- 동일 프로젝트는 Repository 고유 식별자를 기준으로 추적한다.
- 이전 소개 이력은 삭제하지 않는다.
- 반복 선정은 새로운 변화가 있을 때만 허용한다.
- 관찰 프로젝트는 다음 주 우선 확인한다.
- 화제성 점수 변화는 추세 판단용 보조 지표로 사용한다.
- 저장 데이터는 다음 주 분석의 정확성과 중복 방지를 위한 핵심 기준으로 사용한다.
