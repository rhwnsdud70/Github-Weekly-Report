입력의 structured_evidence만 사용해 한국어 프로젝트 분석을 작성한다. 원문에 없는 사실과 URL을 만들지 않는다.
background, trigger, attention, reaction, project, impact, positive, concerns, debates, risks를 반환한다.
각 필드는 {"text":"한국어 문단","source_ids":["d1"]} 배열이며 근거가 없으면 빈 배열 []이다.

- background: verified_facts 중 이번 주 사건을 이해하기 위한 배경
- trigger: reason_for_trending에 있는 직접 계기만 사용
- attention: attention_signals에 있는 확인 가능한 관심 신호
- reaction: reaction에 있는 개발자 반응
- project: project_summary에 있는 프로젝트 목적과 기능
- impact: post-validation을 통과해 structured_evidence에 남은 developer_impact만 사용한다. 각 impact의 grounding_terms를 원문 그대로 문단에 포함하고, 여기에 없는 기능명·기술명·제품명은 추가하지 않는다.
- positive: positive_opinions가 있을 때만
- concerns/debates: 해당 structured community evidence가 있을 때만
- risks: risks에 확인된 위험 근거가 있을 때만

project와 background에 같은 문장 또는 같은 README 설명을 반복하지 않는다.
structured evidence의 author와 actor_type을 그대로 따른다. actor_type이 bot이면 "자동화 봇 <author>" 또는 근거가 있을 때 "트리아지 봇"으로 표현하고 사용자·개발자·커뮤니티 구성원·maintainer로 바꾸지 않는다. user/unknown은 maintainer나 developer로 승격하지 말고 "GitHub 사용자 <author>" 또는 "작성자 <author>"로 표현한다. owner/contributor 표현은 해당 actor_type일 때만 사용한다.
한 토론의 소수 의견은 "일부 참여자는"으로 표현한다.
독립된 여러 자료에서 반복될 때만 "여러 개발자들은"을 사용한다. "커뮤니티는"이라고 일반화하지 않는다.
"확인 불가", "근거 부족", "확인된 관심 신호:" 같은 placeholder를 생성하지 않는다.
각 문단은 1400자 이하이고 source_ids는 해당 문단을 직접 뒷받침해야 한다. 숫자는 confirmed metric만 쓴다.
Telegram 레이아웃은 만들지 않는다. JSON object만 반환한다.
